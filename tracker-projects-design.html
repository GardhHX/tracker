Reasoning, written down (R-31)

  • One big Fraunces number. The detail's "58%" is the single editorial figure and the focal point, the same identity motif as the Finance total and the Tasks section markers; the list echoes it as small tabular percentages.
  • Green means done, nothing else. Progress fill, the completed checkbox, and the primary action carry the one green accent. Status and priority chips stay plain, so completion is the only thing colour points at.
  • Blocked reuses the hatch, not a new red icon. The same hatch flag marks Blocked here, Overdue on Tasks, and Over budget on Finance: one motif for "needs attention", so the vocabulary is learned once.
  • Board and List are one source. The toggle swaps the view, not the data. A blocked task is disabled in both, and its blocker is named on the task, never silently dropped (REQ-07, UX-FLOWS).
  • Guards explain, they don't just disable. "Complete project" opens a plain reason ("5 tasks unfinished") instead of a dead greyed button, matching the rule that completion is refused while tasks are open.
  • Archive is a confirmed, reversible move. The dialog says it only hides the project from the active list and keeps every task and its history, matching archived_at as a separate attribute from done.
  • Empty is explained. A project with no tasks reads "No tasks yet" at 0%, never an unlabelled empty bar (wireframe rule).
  • Two real routes, not invented tabs. The list is /projects and the detail is /projects/:id; the sidebar points only at pages that exist (R-24).
