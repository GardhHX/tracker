Tracker: Wireframe Start to Finish

A wireframe set for the core routes in UX-FLOWS.md: from authentication to settings. Fidelity is deliberately low and grayscale. Layout, components, and interaction rules follow PRD/UX-FLOWS, without yet using the palette or typography from DESIGN.md. Pattern references were pulled from real apps on Mobbin (kanban, finance ledger, habit streaks, focus timer), not copied form-for-form.

Sources: PRD.md · UX-FLOWS.md · DECISIONS.md · DESIGN.md. All amounts and task/project names below are sample data.

Interactions & rules
  • Every card has a "View all" link to its module. No link points to a page that doesn't exist.
  • The Pomodoro card shows next_phase from the server before start; it never runs a phase automatically.
  • Timebox plans Class/Task/Habit/Focus blocks with a start and end time; a plan never runs, checks in, or completes an activity on its own, and the Timebox clock never triggers a Pomodoro phase.
  • Overlapping blocks are allowed; a "Schedule overlap" marker is informational only and never blocks saving.
  • "Start focus" hands off to a manual start in Pomodoro and follows the server's current state/phase; if next_phase is a break or another session is already open, it points to Pomodoro's controls to resolve that first.
  • Cancelling a block keeps its row in history and never cancels an actual running Pomodoro session.
  • The Tasks and Habits cards intentionally show only a couple of items each, not the full list, so the Timebox stays the focal point of the page.
States
  • Empty: the card shows "No tasks yet today" plus a create-task button, never sample data disguised as real.
  • Offline: a text banner above the content, all confirm/check-in actions disabled.

Interactions & rules
  • Toggling List/Kanban/History never changes the data: three views of one source.
  • Kanban drag-and-drop must have a non-drag alternative (a button/status picker) for keyboard use.
  • History reads from the immutable event log toward "done", not the task's current status. Completing a task, reopening it, then completing it again produces two completion events, but it stays one unique task.
  • History groups by the project/title snapshot at the time of the event; a later rename, move, or archive doesn't rewrite old history rows.
  • A task with an unfinished predecessor: "Mark done" is disabled, showing the name of the blocking predecessor.
  • An overdue due date uses the text "Overdue", not color alone.
  • Moving a task that has a dependency shows instructions to remove the dependency first.
  • A done task shows "Reopen" instead of "Mark done"; an archived task separately shows "Unarchive", since archive is an attribute independent from status.
States
  • Empty: "No tasks yet" + a "Create your first task" CTA.
  • Edit conflict: fetch the latest version, show the difference, never silently overwrite.

Interactions & rules
  • Before starting, show next_phase from the server. Focus may pick a task; breaks cannot.
  • After a terminal phase, show a button to start the next phase, it never runs on its own.
  • After 4 completed focus sessions, offer "Start long break".
  • Cancel asks for confirmation and explains the elapsed time stays on record but doesn't count as a completed session.
  • While a focus session is running or paused, changing a linked task's status/project, or archiving its project, is blocked with a message that links back to this session (see Tasks/Projects); editing title/priority/due date is still allowed.
States
  • Countdown hits zero: show "Waiting for phase-end confirmation" until the server reconciles, never switch phase client-side right away.

Interactions & rules
  • A project with no tasks shows 0% progress, not an unexplained blank.

  • The sidebar turns into a topbar with a menu (hamburger) button, openable/closable via keyboard.
  • The 2-column card grid becomes a single full-width column.
  • Kanban columns become a labeled horizontal scroll area bounded by the container, not a page that widens.

Decisions & reasons (R-31)

  1. Fully grayscale inside every frame: so hierarchy and structure are judged apart from color taste. The DESIGN.md palette (single green accent, warm paper) only comes in at the high-fidelity stage.
  2. IBM Plex Sans/Mono chrome font, not Fraunces/Inter: keeps this document read as a structural spec, not a preview of the product's final visual identity.
  3. A single blue accent used only for this page's own annotations & navigation: mirrors the red-pen/marker convention on a printed wireframe, used consistently for one role (spec notes), never inside a frame's own content.
  4. Diagonal hatching for "needs attention" status: overdue and over-budget are marked with a pattern, not color, in line with REQ-15's requirement that status never depend on color alone.
  5. Frames are draggable (resize-horizontal) and use container queries: testing 1440/768/360 px is real reflow, not three static pictures that could silently drift out of sync with the actual CSS.
  6. Elements inside a frame have no real behavior wired up: this is a planning wireframe, not a click-through prototype; faking "live" behavior without a real backend would only hide what's settled from what's still an assumption.
  7. State patterns (empty/loading/error/offline) collected once in one place: avoids repeating eight states on every single screen while still asserting that REQ-16 applies across every module.
